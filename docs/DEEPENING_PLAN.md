# 第二轮：课程深化与逐课图解

## 目标与完成条件

范围为现有 001–100 全部课程，保留问题驱动的四段式主线。每篇须有贴合主题的图解，以及实质性的机制、案例或推演扩充；不能只添加通用总结和装饰图。

- 概念题说明对象、状态与因果关系，给出具体选择边界。
- 代码题解释输入如何变成输出，覆盖关键错误与边界，保留可执行示例及准确输出。
- Review 题展示有问题的起点、触发条件、修复对应关系与验证。
- 场景题提供明确假设、诊断证据、失败路径、恢复和验收方法；模拟数据明确标注。
- 追问链写明答案要点、评价标准与下一问的承接逻辑。
- 每篇至少一张 Mermaid 流程图、时序图或状态图，图下解释如何阅读，避免一张模板套所有题。
- 每篇深化后独立提交，保留首次创作的 100 次提交。按模块同步远程。
- 最终核查全部正文与图解，实际渲染所有 Mermaid，执行全部 Go 示例及相关现有测试，更新验收与写法核查结论。

图解采用文本形式，便于 GitHub 内直接阅读、版本比较和勘误；不强制生成位图。篇幅统计只用于发现遗漏，不作为教学质量的替代指标。
